# Phase 3E: archive controls, deletion, and visual redesign

Date: 2026-08-09
Deployment: `http://192.168.1.20:8080/` on PRIMARY_LAN

## Requested changes

1. Delete unwanted captures after an explicit confirmation.
2. Select a capture date range.
3. Sort by timestamp or starred state, with room for future metrics.
4. Filter by classifier-generated metadata.
5. Give the archive and cards a more polished visual system.

## Deletion model

Delete operates on a capture pair, not on an arbitrary path. The browser sends
the catalog identity (`camera_id` and `pair_key`) and an explicit
`confirmed: true` value. The server looks the pair up itself, validates every
catalogued file path against the media library, and removes both the video and
matching snapshot. Related star and classification rows are removed in the same
catalog transaction.

Before the catalog transaction commits, files are atomically staged inside the
library. If the database operation fails, they are restored to their original
paths. After a successful commit, the staged files are permanently removed.
The UI describes that result accurately: there is no undo or recycle bin.

Deletion is available from both gallery cards and the dedicated watch page.
The browser always asks:

> Permanently delete this capture? This removes the video and its matching
> snapshot from the Pi. This cannot be undone.

## Archive controls

Filtering and sorting happen in the browser after the gallery loads, so the
controls respond immediately and make no network request:

- inclusive From and To capture dates;
- Newest first, Oldest first, and Starred first;
- All captures, Starred only, Identified species, Awaiting identification,
  Bird detected, and No bird detected;
- a Reset action and live visible/total capture count.

Each card contains machine-readable date, timestamp, star, classification, and
bird-detection attributes. Future classifier metrics can be added as new card
attributes and options without changing media paths or filenames.

## Visual system

The redesigned page uses the existing captures as the visual focus:

- larger image-led cards with a 16:10 crop, restrained depth, and subtle hover
  motion;
- floating Star control and capture-time overlay on each image;
- clearer hierarchy for date, species state, and primary/secondary actions;
- a compact archive toolbar, live summary pills, and intentional empty states;
- responsive two-column controls and single-column cards on narrow screens;
- visible keyboard focus states and native labelled form controls.

The implementation remains dependency-free: HTML, CSS, and small progressive
JavaScript enhancements are generated by the Python server.
